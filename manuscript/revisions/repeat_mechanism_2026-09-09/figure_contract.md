# 本轮图件合约

使用既有 Python / matplotlib 流程。采用 183 mm 双栏宽度、白底、可编辑 PDF/SVG、300 dpi PNG、600 dpi TIFF，最小图中文字 6.5 pt。图件回答计算支持的问题，不预设干预一定成功。数据来自本轮已完成的统计表，不在绘图脚本重算统计或填补缺失值。

保留六幅主图和五幅补充图。主图 1、2、4、5 及补充图 1、2、4、5 复用 v0.20 的相同数据与既有脚本；本轮没有改变这些分析。主图 3、6 与补充图 3 更新。全部 11 图最终通过交付的统一入口重绘并核对。

主图 3 是机制与决策的定量复合图。面板 a 比较五档工作资格下，同一八小时/十二小时间隔全额请求的两个控制器在新确认集上的成功率，显示单侧 95% Wilson 下界。面板 b 显示公开选取规则确定的开发情景中的恢复峰值，说明原控制器失败与全部窗口记忆的差别；这是解释性个例，不是新的独立统计证据。面板 c 比较 10% 工作资格下四种调用安排的开发选值与独立确认状态，无入选显示为文字，不能绘成零物理容量。

主图 6 保留单次事件的三种成本机制、时长及等待单价比较。面板 c 替换为新控制器按调用安排选出的重复请求所对应的自然空闲成本，展示全部五档资格。只有开发入选且确认通过才标为可供选择的方案，确认失败仍保留且用不同符号明确表示。费用是声明参数下的决策统计量，不是带有置信区间的利润估计。

补充图 3 展示新确认情景的配对排队 GPU 小时及累计错过期限工作轨迹，并报告开发全额请求下的失败类型与完整候选选值。均值曲线的带为情景第 5–95 百分位，不标作均值置信区间。累计量必须先在每个情景内计算，再汇总百分位。开发结果和新确认结果分面标明，不混合统计。

数值列映射及全部输入哈希进入图件清单。现成逐小时曲线来自全部相应情景，没有为图形美观抽样；示例情景及其选取理由单独保存。40% 与 60% 仍带额外假设标记。导出后执行源码预检、PDF 字号审计及逐面板视觉检查。
